# SAM 3D single view vs multi-view variants

Read 2026-10-29 from primary sources listed at the end; builds on `sam3d.md`. Paper text via fetch-tool summaries; repo files/issues/API data read as plain text. Nothing cloned, installed, or run. UNVERIFIED = not confirmed in a primary source.

Primary path for P3.1/P3.3 is official single-view SAM 3D Objects: several samples from the best keyframes, then P3.2 registration. MV-SAM3D is a shape-only bake-off arm behind the same adapter, not a dependency or pose source. Multi-view fusion does not improve pose/scale (MV-SAM3D pose comes from view 0 only; its layout gains come from post-hoc metric-depth fitting, which P3.2 already does). It improves shape on clean renders (GSO-30 Chamfer −59% at 5 views) but only ~1-5% over the best single view on occluded real scenes; view choice matters more. Sampling cost grows ~linearly with views; either way the benchmark costs tens of dollars on Modal.

Quality details: MV-SAM3D paper (arXiv 2603.11633v2): GSO-30 Chamfer SAM 3D 42.0 → 20.2 (2 views) → 17.3 (5 views) (clean unoccluded renders, known poses); novel-view PSNR 19.82 → 23.45 → 25.22; own multi-object scenes Acc@5cm 55.66/60.23/91.66 (no metric/unit/view-count definitions; Table 5 vs Table 3 mismatch unexplained; refinement optimises per-object similarity vs metric-depth Chamfer + collision/contact terms). Code: `POSE_KEYS` are "View 0 only" (`multi_view_utils.py`); released `--run_pose_optimization` is Chamfer-to-DA3-points only (no collision/contact/layout terms; issue #19 reports worse ScanNet++ layouts); users find plain average beats weighted (issues #9/#18). Independent Scene-SAM3D (arXiv 2607.16805v1, repo empty): best-view selection cuts Chamfer ~1/3 (Replica 61.96→41.60, ScanNet++ 79.25→57.71); 4-view fusion adds ~1-5% (39.37/57.36); plain averaging can trail one good view. SAM 3D paper (arXiv 2511.16624): SA-3DAO shape best-of-7 (F1 0.2344, Chamfer 0.0400); joint layout 15-21° mean ICP-Rot (below the 10° gate unaided, with or without fusion — P3.2/P3.4 decide the gate); pointmap on/off indifferent for shape/texture (App. E.5, 48/48%); limits: 64³ grid loses thin detail, single-object/no-contact reasoning, pose-unaware texture on symmetric objects, compounding mask errors. Small-object anecdote (wyim-pgl, one capture): 8 mm bearing at 18-28 px → flat-sliced sphere (12% hull volume); cup height 105-109 vs 110 mm (rim/base −4/+7%); outputs "not in physical units" there, scaled by reference sphere (conflicts with DA3 "already in meters").

Cost basis: single-view 10-30 s/call H100 (user figure widened for mesh/post), MV-5-view single + ~4.3 s/extra view (Scene-SAM3D Table 4 H200) widened 3× → 30-90 s; A100 1.5× H100 (UNVERIFIED); 48 container starts × 40 s; DA3 ~60 s/video (UNVERIFIED). Three-arm P3.3 bake-off with reruns ≈ $100 — engineering time and the DA3 NC license decide, not cost. Four single-view samples from four keyframes ≈ one MV sample over four views.

Fit: MV layout needs `scene/images/*.png`, per-object RGBA masks, `da3_output.npz` (`depth`, `pointmaps`, `pointmaps_sam3d`, `extrinsics` world-to-camera, `intrinsics`, `image_files`, `process_res` 504) plus `scene.glb` + `hf_alignment`; view 0 is reference; known-pose use is untested (hand-written npz with pycolmap extrinsics/intrinsics + dense per-keyframe depth, or DA3 `inference(extrinsics, intrinsics, align_to_input_ext_scale=True)` — sparse pycolmap points insufficient). Outputs `result.glb` (canonical mesh), `result.ply`, `params.npz` (R/t/s to view-0 camera + pointmap scale/shift). P3.2's similarity fit to the marker-scaled cloud + multi-view masks already covers MV's post-refinement role; MV helps, if at all, on occluded-object shape for P3.2's point-to-mesh fit and Phase 4 stability.

License/maturity: MV-SAM3D 2025-11-27, 561 stars/51 forks at read, upstream PR #37 (simple average) unmerged; forks wyim-pgl (installer, `--low_vram`, batch, fixes, 193 tests), `Roworks-ai` (PR #37 on Replicate/Cog), superseded `devinli123/multi-view-sam-3d-objects`. No official multi-view (README news 2025-11-19/2026-06-01/2026-06-02; single-view-only per issue #21). SAM License unchanged for SAM 3D (D-005); DA3 giant weights add a second non-commercial component (DA3 code Apache-2.0; BASE/SMALL/METRIC-LARGE/MONO-LARGE weights Apache-2.0) — avoided by feeding our own npz. Not legal advice.

Recommendation (opinion, 2026-10-29): P3.1 adapter on official single-view `Inference` with samples spread over top P2.4 keyframes (view choice is the larger lever); P3.2 registration unchanged (no MV pose optimiser); P3.3 adds MV as a fourth arm only after single-view runs end-to-end (same keyframes/masks, hand-written npz, one sample; score point-to-mesh + Phase 4 stability by tier/occlusion; keep only on medium/hard wins; pin commit, prefer wyim-pgl fixes); no DA3 giant weights (use VGGT/rasterised-pycolmap depth, keeps marker metric scale).

# SAM 3D Objects: API, multi-object use, hardware, license

Read 2026-10-28 from primary sources listed at the end. Nothing downloaded or run. Fetch-tool summaries mark code quotes as reported, not locally copied.

Single image + mask per call (not multi-view); several objects from one frame cost one full call each (only image/pointmap load is shareable); per-object frame quality beats shared keyframes; no official multi-view (community MV-SAM3D + forks + upstream PR #37 only); optional pointmap must be dense per-pixel H×W×3, not sparse COLMAP points.

Entry point: `notebook/inference.py` class `Inference` wrapping `InferencePipelinePointMap` (`sam3d_objects/pipeline/inference_pipeline_pointmap.py`). `Inference.__call__(image, mask, seed=None, pointmap=None) -> dict`; mask is effectively required (merged unconditionally as RGBA alpha via `mask.astype(np.uint8)*255`). Pipeline `run()` accepts `stage1_only`, mesh/texture/layout postprocessing flags, `use_vertex_color`, step counts, distillation flags, `pointmap`, `decode_formats`, `estimate_plane`.

Pointmap: optional; when absent, computed from the image by the configured depth model. Format H×W×3 per-pixel xyz (resized nearest-neighbour on mismatch), converted from R3 camera space to PyTorch3D space (eye `[0,0,-1]`, up `[0,-1,0]`); intrinsics inferred from it when passed. Normalised internally (`pointmap_scale`/`pointmap_shift`, unnormalised copy kept); metric status unstated in code. Paper §2.2/§4/E.5: optional conditioning (e.g. iPhone LiDAR or monocular depth); shape/texture largely independent of it; layout (pose/scale) is the affected term. Sparse COLMAP points have no code path — densify/rasterise (NaN-tolerance unverified) or use a dense depth model.

Outputs: pose-decoder results (`rotation`, `translation`, `scale`) plus `glb`/`gaussian`, `pointmap`, `pointmap_colors`; quick start exports `output["gs"].save_ply(...)`; `make_scene` reads `gaussian`+pose+scale. Mesh needs mesh postprocessing/texture baking on (disabled by `Inference`, enabled by `run` defaults). Scale is in normalized camera coordinates (paper §3.1.2; code multiplies by `downsample_factor`, `refine_scale` averages channels) — not guaranteed metric; registration to the marker-scaled cloud (P3.2) is required. One sample per call (`seed` = `torch.manual_seed` only); several seeds = several calls. Speed knobs: stage step counts + distillation flags (paper: 25→4 NFE, "sub-second" with hardware unstated).

Multi-object (`notebook/demo_multi_object.ipynb`): `[inference(image, mask, seed=42) for mask in masks]` then `make_scene(*outputs)` — one full call per mask, no batching ("no batch dimension"), layout composed afterward from independent per-object poses in the same camera frame (`make_scene` internals unread; independent poses can interpenetrate/float per MV-SAM3D paper). Runtime scales linearly with mask count. Paper §4.1 scenes are mostly single-object; no many-object saving claimed.

Hardware/access/license: NVIDIA GPU ≥32 GB VRAM, 64-bit Linux (`doc/setup.md`); ~20 GB weights on disk (third-party, unverified in primary sources); PyTorch3D may need GPU-node build. Hugging Face `facebook/sam-3d-objects` gated (name, birth date, org); unavailable in comprehensively sanctioned jurisdictions; no Inference Provider deployment. SAM License on code+checkpoints (non-exclusive/worldwide/royalty-free; law/trade-control compliance; no reverse engineering; no ITAR/military/nuclear/espionage; acknowledge in publications; passthrough on distribution; outputs AS-IS; own derivatives (§5.a); termination/modification clauses; no outputs/commercial-use restriction reported — not legal advice, see `docs/licenses.md`). No documented Modal/Baseten SAM 3D recipe found (D-015 already flags this); Roboflow self-host is third-party.

Consequences for P2.4/P3.1: keyframes are per object (top 3-5 by mask area/occlusion/border/sharpness) — one image+mask per call, so no shared-frame discount. Per-keyframe camera pose + intrinsics must be stored for future dense-map rasterisation or default depth. P2.2/P2.3 unchanged: clean binary masks per frame in, lifted 3D points for registration (not SAM 3D input). Pass pointmaps only after a P3.3 A/B test (pose/scale refined against metric cloud anyway).

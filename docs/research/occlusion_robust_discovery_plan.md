# Object discovery gaps and visual prompts

Baseline: router sends 3 evenly spaced frames to the VLM, then one generic SAM 3.1 concept ("objects on a table"). Dev recall is 56 of 59 (`benchmark/results/p2_eval_segmentation_dev.json`): missing are one s13 stack box, the s18 pliers, the s24 glossy cube. Test misses s15 obj_021 and s16 obj_003 (`docs/final_benchmark.md`) are not tuning targets. The known misses look like SAM prompt misses (visible objects the generic concept does not fire on), not occlusion misses.

Guarantees the design targets: (1) coverage — every table-workspace cell seen unoccluded by ≥k router frames, measured on a height map of the sparse cloud and recorded; (2) audit — every router noun and every above-table point cluster is either explained by a track or written to the QA report. Objects hidden from every frame and absent from the cloud are input failures (capture gate), not recoverable downstream.

## SAM 3.1 visual prompts for video

Meta Model API accepts box/point prompts for video. Protocol (`protocol/sam3.md` in `meta-models/meta-sam`, PR 17, merge `6bfaa17`): one block per source frame opened by `<Nf>`; comma-separated segments of bare object id + tokens (e.g. `1<|box;...|>`); box `<|box;x1=...;y1=...;x2=...;y2=...;w=...;h=...|>` (x1/y1/x2/y2 order, x2/y2 inclusive, ≤1 box per object per frame); point `<|point;x=...;y=...;w=...;h=...|>` (positive default, leading `-` negative); `w`/`h` are displayed media pixels after rotation; coordinates floored and clamped; no mask tokens as prompts. Same id across frames is the same object; new id is a new object; one appearance per id per frame. Responses preserve sent ids (`<Nf>id<|box;...|><|mask;...|>`, read by `models/hosted.py::parse_sam_text`). `metadata.propagation_direction` selects tracked frames; text carries a noun phrase or object prompts, never both; docs state 16 objects per request. Playground test (PR 19): objects boxed on frames 30 and 120 tracked over all 200 frames. Docs: `https://dev.meta.ai/docs/sam/segmenting`.

Live probe 2026-11-02 (`benchmark/results/s12_9_probe.json`, run `s02_b`): 4/4 requests accepted; ids preserved (incl. non-contiguous id 2); box tracks cover all 50 clip frames with prompted-frame IoU 0.56-0.64 vs projected ground-truth boxes. Request marker is `<30f>`, not `<N30>`. Negative control (160 px box on bare table): table patch on 11/50 frames, fill decaying 0.61→0.02 — prompted-frame fill/IoU gates alone (0.61/~0.60) do not reject it, so track length and fill decay must weigh too. Consequence: object prompts are just prompt strings, so `VideoSamClient.track(video, prompt, direction)` is unchanged and the cluster-box path is cheap.

## Pipeline facts

Source priority for "where to look": geometry (point-cloud clusters — no VLM guess, misses featureless objects) > VLM noun inventory (finds point-less objects; P2.1 showed 5.6× false positives) > overlay audit (catches residuals; extra VLM call). View selection feeds the router; the cloud is used after tracking to find unexplained tracks and place box prompts. Order in `SegmentationStage.run` (`stages/segmentation_stage.py`): sparse cloud → view selection → router (map-reduce) → generic track → marker filter/repair/lift/fit/duplicates → gap fill (≤1 round: noun requests for shortfall + one box request for unexplained clusters → merge/repair/lift/fit) → discovery check → keyframes/flags/material pass. With `views.mode: even` and `gap_fill.enabled: false` output incl. `route.json` is byte-identical to pre-discovery behavior (pinned by test).

Schema (`src/video2sim/schemas.py`, human-approved; old payloads still validate): `DiscoveryCheck` (`view_frames`, `view_coverage` ∈ [0,1], `listed` lower-bound inventory count, `tracked`, `missing_suspected`, `unmatched` nouns, `unexplained_clusters`, `recovered`, `video_requests` ≥1); `ObjectInstance.found_by ∈ {generic, noun, cluster_box}` (default `generic`); `Instances.discovery`. QA report (`stages/qa_report.py`) shows a Discovery block with `unmatched`/`unexplained_clusters` as warnings and per-object `found_by`.

Cost today: 1 VLM call + 1 video request (~$0.017 for 84 frames at $0.20/1k, min 50/request). Build status and acceptance live in `PLAN.md` section 12 item 9.
